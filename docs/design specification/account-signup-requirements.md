# アカウント作成機能 要件定義書

## 1. 概要

### 1.1 目的

新規ユーザーがメールアドレス、パスワード、ユーザー名を登録し、在庫管理システムを利用開始できるようにする。

### 1.2 対象ユーザー

まだアカウントを持っていないユーザー。

### 1.3 前提

- 認証基盤は Supabase Auth を使用する。
- メールアドレス確認は本リリースでは行わず、登録完了後すぐにログイン可能とする。
- 登録完了後は完了メッセージを表示し、ログイン画面へ誘導する。
- ユーザー名はシステム内で一意とする。
- 自己登録で作成されるユーザーの初期権限は `general` 固定とする。
- 管理者、MG などのロールベース権限管理と管理者による権限変更は別機能として扱う。自己登録画面では権限を選択させず、初期権限は常に `general` とする。
- ユーザー招待、ユーザー承認は本リリースでは扱わない。
- Supabase の RLS は有効化し、プロフィール情報は本人のみ参照できるようにする。

## 2. 画面要件

### 2.1 画面一覧

| No. | 画面名 | 概要 |
| --- | --- | --- |
| 1 | アカウント作成画面 | 新規ユーザーが登録情報を入力し、アカウントを作成する |
| 2 | ログイン画面 | 登録済みユーザーがログインする。アカウント作成画面から遷移できる |

### 2.2 アカウント作成画面の表示項目

| 項目 | 種類 | 必須 | 説明 |
| --- | --- | --- | --- |
| メールアドレス | 入力欄 | 必須 | ログインに使用するメールアドレス |
| パスワード | パスワード入力欄 | 必須 | ログインに使用するパスワード |
| パスワード確認 | パスワード入力欄 | 必須 | 入力ミス確認用 |
| ユーザー名 | 入力欄 | 必須 | 画面上に表示する名前 |
| アカウント作成ボタン | ボタン | 必須 | 入力内容を送信してアカウントを作成する |
| ログイン画面へのリンク | リンク | 必須 | 既にアカウントを持っているユーザーをログイン画面へ誘導する |

### 2.3 登録完了時の表示

登録が完了した場合、以下のメッセージを表示する。

```text
アカウント作成が完了しました。
ログインしてください。
```

完了メッセージ表示後、ユーザーがログイン画面へ移動できる導線を表示する。

## 3. 入力項目

| 項目 | 必須 | 形式・備考 |
| --- | --- | --- |
| メールアドレス | 必須 | メールアドレス形式。ログインIDとして利用する |
| パスワード | 必須 | 8文字以上 |
| パスワード確認 | 必須 | パスワードと同じ値 |
| ユーザー名 | 必須 | 表示名として利用する。システム内で一意 |

## 4. 入力チェック

### 4.1 クライアント側チェック

ユーザーの入力時または送信時に、以下のチェックを行う。

| チェック内容 | エラーメッセージ |
| --- | --- |
| メールアドレスが入力されているか | メールアドレスを入力してください |
| メールアドレスの形式が正しいか | 正しいメールアドレスを入力してください |
| パスワードが入力されているか | パスワードを入力してください |
| パスワードが8文字以上か | パスワードは8文字以上で入力してください |
| パスワード確認が入力されているか | パスワード確認を入力してください |
| パスワードとパスワード確認が一致しているか | パスワードが一致しません |
| ユーザー名が入力されているか | ユーザー名を入力してください |

### 4.2 サーバー側チェック

登録処理時に、クライアント側と同等の入力チェックに加えて以下を確認する。

| チェック内容 | エラーメッセージ |
| --- | --- |
| 同じメールアドレスが登録済みでないか | アカウント作成に失敗しました。入力内容を確認してください |
| 同じユーザー名が登録済みでないか | このユーザー名はすでに使用されています |
| Supabase Auth でアカウント作成に失敗していないか | アカウント作成に失敗しました。時間をおいて再度お試しください |

メールアドレス重複時はアカウント列挙を避けるため、登録済みであることを直接示すメッセージは表示しない。

## 5. 登録処理

### 5.1 登録する情報

| 項目 | 保存先 | 説明 |
| --- | --- | --- |
| ユーザーID | Supabase Auth / プロフィールテーブル | Supabase Auth が発行するユーザーID |
| メールアドレス | Supabase Auth | ログインに使用する |
| パスワード | Supabase Auth | 平文では保存しない。Supabase Auth の仕組みで安全に管理する |
| ユーザー名 | プロフィールテーブル | 画面上に表示する名前。一意制約を設ける |
| 権限 | プロフィールテーブル | 自己登録では `general` 固定 |
| 作成日時 | Supabase Auth / プロフィールテーブル | アカウント作成日時 |

### 5.2 処理フロー

1. ユーザーがアカウント作成画面で入力項目を入力する。
2. クライアント側で入力チェックを行う。
3. Server Action 経由で登録処理を実行する。
4. サーバー側で入力チェック、メールアドレス重複、ユーザー名重複を確認する。
5. サーバー側で Supabase Auth の管理 API を使用し、メール確認済み扱いのユーザーを作成する。
6. Supabase Auth のユーザーIDに紐づくプロフィール情報を保存し、権限は `general` 固定で保存する。
7. 登録完了メッセージを表示し、ログイン画面へ誘導する。

### 5.3 エラー時の扱い

- 入力内容に誤りがある場合、アカウントは作成せず、画面上にエラーメッセージを表示する。
- Supabase Auth でアカウント作成に成功し、プロフィール情報の保存に失敗した場合は、サーバー側で Supabase Auth ユーザーを削除して不整合を残さない。
- 予期しないエラーは共通ロガーに記録し、ユーザーには詳細な内部情報を表示しない。

## 6. 認証・権限要件

### 6.1 認証

- ログインにはメールアドレスとパスワードを使用する。
- メールアドレス確認は本リリースでは行わない。Supabase Auth 側では自己登録ユーザーが登録直後にログインできる設定とする。
- 登録完了時点では自動ログインせず、ユーザーにログイン画面からログインしてもらう。

### 6.2 権限

- 自己登録で作成されるユーザーの権限は `general` とする。
- 自己登録後の権限変更は、管理者のみがユーザー管理画面から行う。
- Supabase 側では RLS を設定し、プロフィール情報は本人のみ参照できるよう制御する。
- Supabase の Service Role キーはサーバー側のみで使用し、クライアントへ露出しない。

## 7. 非機能要件

### 7.1 セキュリティ

- パスワードをアプリケーションDBへ平文保存しない。
- 登録処理は Server Action 経由で実行する。
- クライアントから Service Role キーを使用しない。
- サーバー側でも必ず入力値を検証する。
- クライアントから権限情報を送信しない。初期権限はサーバー側で `general` を設定する。
- RLS により、クライアントからの直接アクセスでも他ユーザーのプロフィール情報を参照できないようにする。
- 登録処理にはレート制限を設け、短時間に大量のアカウント作成が行われないようにする。

### 7.2 ユーザビリティ

- 入力エラーは対象項目が分かる位置に表示する。
- 登録処理中は二重送信を防ぐため、アカウント作成ボタンを無効化する。
- 既にアカウントを持っているユーザーがログイン画面へ戻れる導線を表示する。

### 7.3 レスポンシブ対応

- PC ブラウザを主対象とし、スマートフォン・タブレットでも入力と送信ができるようにする。

## 8. 受け入れ基準

1. アカウント作成画面が表示できる。
2. メールアドレス、パスワード、パスワード確認、ユーザー名を入力できる。
3. アカウント作成画面で権限を選択できない。
4. 必須項目が未入力の場合、登録できずエラーメッセージが表示される。
5. メールアドレス形式が不正な場合、登録できずエラーメッセージが表示される。
6. パスワードが8文字未満の場合、登録できずエラーメッセージが表示される。
7. パスワードとパスワード確認が一致しない場合、登録できずエラーメッセージが表示される。
8. 登録済みメールアドレスでは登録できない。
9. 登録済みユーザー名では登録できない。
10. 正常時に Supabase Auth へアカウントが作成され、プロフィール情報が保存される。
11. 作成されたプロフィールの権限は `general` で保存される。
12. 登録完了後に「アカウント作成が完了しました。ログインしてください。」と表示される。
13. 登録完了後、ログイン画面へ移動できる。
14. 作成したアカウントでログインできる。
15. RLS により、他ユーザーのプロフィール情報を参照できない。

## 9. 想定外（本リリースのスコープ外）

将来的に検討する可能性があるが、本リリースでは対象外とする項目を明示しておく。

- メールアドレス確認
- パスワードリセット
- ソーシャルログイン
- 多要素認証
- 管理者によるユーザー承認
- 管理者、MG、一般のロール別アクセス制御
- 権限変更画面
- ユーザー招待
- ユーザー退会
- アカウント情報変更
- プロフィール画像
